# Warehouse & Asset Management System

نظام مؤسسي متكامل لإدارة المستودعات والأجهزة والعقود والصيانة والضمان والمستخدمين والصلاحيات.

## البنية

```
warehouse-system/
├── backend/     Node.js + TypeScript + Express + Prisma + PostgreSQL
├── frontend/    React + TypeScript + Vite + Tailwind (عربي/إنجليزي RTL/LTR)
└── docs/        وثائق المعمارية
```

## ما تم بناؤه (Backend — يعمل فعليًا)

- **قاعدة بيانات كاملة** (`backend/prisma/schema.prisma`) لكل الكيانات: المديريات، المراكز، المستودعات،
  الموظفين (مع سجل نقل كامل)، الأصناف، الأجهزة، الموردين، العقود، دفعات التوريد، الضمان، عقود الصيانة،
  طلبات الصيانة ومراحلها، حركات المخزون (توريد/صرف/مرتجع/مناقلة)، تسليم/إرجاع الأجهزة، الإشعارات،
  المرفقات، المستخدمين، الأدوار، الصلاحيات (RBAC بنطاقات)، سجل التدقيق.
- **مصادقة JWT** (access + refresh) + تشفير bcrypt.
- **RBAC حقيقي** بصلاحيات (View/Create/Edit/Delete/Approve/...) ونطاقات (مديرية/مركز/مستودع).
- **Audit Log** مركزي مكتوب ضمن نفس الـ Transaction لكل عملية إنشاء/تعديل/حذف/اعتماد.
- **حساب تأخير التوريد** تلقائيًا حسب الصيغة المطلوبة بالضبط + **`GET /api/contracts/expiring`**.
- **حركات المخزون** (توريد/صرف/مناقلة) كل عملية ضمن Prisma Transaction واحدة — فشل جزئي = تراجع كامل،
  مع منع تكرار Serial Number ومنع الصرف عند نقص الرصيد.
- **دورة الصيانة الكاملة** (12 مرحلة) + تحديد التغطية تلقائيًا (ضمان / عقد صيانة / خارج التغطية)
  + مسار اعتماد الصيانة خارج التغطية.
- **محرك تنبيهات** يفحص العقود (90/60/30/15/7/0 يوم)، الضمانات، التوريدات المتأخرة، المخزون المنخفض.
- **تقارير CSV** قابلة للتصدير: المخزون، الأجهزة، العقود، التوريدات المتأخرة، الصيانة.
- Seed script لإنشاء الأدوار (Super Admin, أمين مستودع, مدير العقود) وصلاحياتها ومستخدم أولي.
- اختبارات وحدة فعلية لمنطق حساب التأخير ومستوى خطورة انتهاء العقود.

## ما تم بناؤه (Frontend — يعمل فعليًا)

React + TypeScript + Vite + Tailwind، عربي/إنجليزي مع RTL/LTR ديناميكي، متصل بكل الـ APIs أعلاه:
تسجيل الدخول (JWT + تجديد تلقائي)، Dashboard بالبطاقات والألوان، المراكز والمديريات، الموظفين
(مع نقل وتاريخ)، الموردين، المستودعات، الأصناف، الأجهزة (مع صفحة "جواز سفر الجهاز" الكاملة)،
العقود (بالألوان حسب الخطورة) وتفاصيلها ودفعات التوريد، شاشة توريدات عامة، الاستلام، الصرف،
المناقلات، الصيانة (بأزرار تقدم دورة الحياة والاعتماد)، الضمان، المستخدمين، الأدوار والصلاحيات،
الإشعارات، التقارير (تصدير CSV)، سجل العمليات.

## التشغيل محليًا

### الخادم (Backend)
```bash
cd backend
cp .env.example .env     # عدّل DATABASE_URL وأسرار JWT
npm install
npm run prisma:migrate
npm run prisma:seed      # admin / ChangeMe@123
npm run dev              # http://localhost:4000
```

### الواجهة (Frontend)
```bash
cd frontend
npm install
npm run dev               # http://localhost:5173 (يتصل بـ 4000 عبر proxy)
```

سجّل الدخول بـ `admin` / `ChangeMe@123` ثم غيّرها فورًا.

### الاختبارات
```bash
cd backend && npm test
```

## ملاحظة مهمة حول بيئة البناء

بيئة العمل التي بُني بها هذا المشروع لا تملك اتصال إنترنت، لذا لم يتمكن من تشغيل
`npm install` أو الاختبارات فعليًا أثناء الكتابة. كل الملفات مكتوبة ومراجَعة يدويًا بعناية
وتتبع أنماط Prisma/Express/React القياسية، لكن **شغّل `npm install && npm test` في كلا
المجلدين فور تحميل المشروع على جهازك للتأكد قبل الاعتماد عليه في بيئة إنتاج**.

## ما لم يُبنَ بعد / يحتاج تحسينًا لبيئة إنتاج حقيقية

- رفع ومعاينة المرفقات (الـ Backend يدعم الربط بالبيانات؛ واجهة الرفع الفعلية للملفات غير مبنية)
- تصدير PDF/Excel للتقارير (مبني حاليًا CSV فقط؛ يمكن إضافة PDF/Excel بنفس النمط)
- Scheduled Job فعلي (node-cron) لاستدعاء `generateAlerts` دوريًا بدل الاستدعاء اليدوي
- شاشات فلترة وبحث متقدم شاملة عبر كل الوحدات (البحث الأساسي بالـ API متوفر عبر query params)
- اختبارات Integration شاملة لكل Endpoint (تحتاج قاعدة بيانات حقيقية تعمل أثناء الاختبار)
- ملفات Docker / docker-compose لتسهيل النشر
- صفحة "إعدادات النظام" العامة (Settings)

هذه التحسينات تُبنى بنفس نمط الكود الموجود دون أي إعادة هيكلة.

# Warehouse & Asset Management System

نظام مؤسسي متكامل لإدارة المستودعات والأجهزة والعقود والصيانة والضمان والمستخدمين والصلاحيات.

## البنية

```
warehouse-system/
├── backend/          Node.js + TypeScript + Express + Prisma + PostgreSQL
├── frontend/         React + TypeScript + Vite + Tailwind (عربي/إنجليزي RTL/LTR)
├── docker-compose.yml تشغيل كامل النظام بأمر واحد
└── docs/             وثائق المعمارية
```

## التشغيل السريع عبر Docker (الطريقة الموصى بها)

```bash
docker compose up --build
```

هذا يشغّل: قاعدة بيانات PostgreSQL + الخادم (منفذ 4000) + الواجهة (منفذ 8080).
بعد الإقلاع، نفّذ مرة واحدة لإنشاء الأدوار ومستخدم البداية:

```bash
docker compose exec backend npx prisma db seed
```

افتح `http://localhost:8080` وسجّل الدخول بـ `admin` / `ChangeMe@123` ثم غيّرها فورًا.

## التشغيل اليدوي المحلي (بدون Docker)

### الخادم (Backend)
```bash
cd backend
cp .env.example .env     # عدّل DATABASE_URL وأسرار JWT
npm install
npm run prisma:migrate
npm run prisma:seed      # admin / ChangeMe@123
npm run dev              # http://localhost:4000
```

### الواجهة (Frontend)
```bash
cd frontend
npm install
npm run dev               # http://localhost:5173 (يتصل بـ 4000 عبر proxy)
```

### الاختبارات
```bash
cd backend && npm test
```

## الوحدات المكتملة والعاملة فعليًا

**قاعدة البيانات**: كل الكيانات المطلوبة (30+ نموذج) بعلاقات وفهارس وقيود فريدة صحيحة، بما فيها
الهيكل التنظيمي الثلاثي: كل **مركز** يرتبط إلزاميًا بـ **إدارة + مديرية + قسم**، مع تتبّع اسم
منشئ كل سجل تلقائيًا من الجلسة (`createdByUserId`).

**المصادقة والصلاحيات**: JWT (access + refresh) + RBAC حقيقي بنطاقات (مديرية/مركز/مستودع)،
صلاحيات منفصلة لكل من الإدارات/المديريات/الأقسام/المراكز بحيث يمكن منح مستخدم صلاحية إنشاء
إدارة دون صلاحية إنشاء مديرية مثلًا.

**الحذف الآمن**: كل عمليات الحذف ناعمة (تعطيل الحالة) وتتطلب **سبب حذف إلزاميًا**:
- حذف مركز → ممنوع إن وُجد موظف فعّال تابع له
- حذف إدارة/مديرية/قسم → ممنوع إن وُجد مركز مرتبط به

**سجل التدقيق (Audit Log)**: مركزي، مكتوب ضمن نفس الـ Transaction لكل عملية، غير قابل للحذف.

**حركات المخزون**: توريد/صرف/مناقلة كل عملية ضمن Prisma Transaction واحدة (فشل جزئي = تراجع
كامل)، مع منع تكرار Serial Number ومنع الصرف عند نقص الرصيد.

**العقود والتوريد**: حساب تأخير التوريد تلقائيًا + `GET /api/contracts/expiring` + ألوان الخطورة.

**الصيانة**: دورة حياة كاملة (12 مرحلة) + تحديد التغطية تلقائيًا (ضمان/عقد صيانة/خارج التغطية)
+ مسار اعتماد للصيانة خارج التغطية.

**الإشعارات**: محرك تنبيهات يفحص العقود (90/60/30/15/7/0 يوم) والضمانات والتوريدات المتأخرة
والمخزون المنخفض — **مجدول تلقائيًا كل ساعة عبر node-cron** (`backend/src/jobs/scheduler.ts`)،
بالإضافة إلى إمكانية التشغيل اليدوي عبر `POST /api/notifications/generate`.

**المرفقات**: رفع/تنزيل/حذف فعلي للملفات (PDF, صور, Word, Excel، حتى 15MB) عبر Multer، مرتبطة
بالعقود والأجهزة والدفعات وحركات التسليم وسندات التوريد/الصرف وطلبات الصيانة. مكوّن
`AttachmentsPanel` جاهز في الواجهة ومُدمج فعليًا في صفحتي تفاصيل الجهاز والعقد.

**التقارير**: تصدير CSV للمخزون، الأجهزة، العقود، التوريدات المتأخرة، الصيانة.

**الواجهة**: كل الشاشات الـ21 (بما فيها الإعدادات) بتصميم مخصص (Ink + Petrol + Tajawal/IBM Plex
Arabic + أيقونات lucide-react + بطاقات الصنف Asset Tag)، عربي/إنجليزي RTL/LTR ديناميكي.

## ملاحظة مهمة حول بيئة البناء

بيئة العمل التي بُني بها هذا المشروع لا تملك اتصال إنترنت، لذا لم يتمكن من تشغيل `npm install`،
`docker compose build`، أو الاختبارات فعليًا أثناء الكتابة. كل الملفات مكتوبة ومراجَعة يدويًا
بعناية، لكن **شغّل `npm install && npm test` (أو `docker compose up --build`) فور تحميل المشروع
على جهازك للتأكد قبل الاعتماد عليه في بيئة إنتاج** — وأرسل لي أي خطأ يظهر لأصلحه فورًا.

## ما لم يُبنَ بعد / تحسينات مستقبلية

- تصدير PDF/Excel للتقارير (مبني حاليًا CSV فقط؛ نفس النمط يُضاف بسهولة)
- شاشات فلترة وبحث متقدم شاملة عبر كل الوحدات (البحث الأساسي متوفر عبر query params في الـ API)
- اختبارات Integration شاملة لكل Endpoint (تحتاج قاعدة بيانات حقيقية أثناء الاختبار)
- معاينة الصور داخل لوحة المرفقات (حاليًا تنزيل فقط، لا معاينة مباشرة)

هذه التحسينات تُبنى بنفس نمط الكود الموجود دون أي إعادة هيكلة.
